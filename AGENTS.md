# Rules
### General
- Always use simple language for conversing with the user, writing code comments & docstrings, and writing documentation. Use topic-specific terminology when appropriate.

### Writing Code
- Code edits which expected to be over 50 lines should always be planned first and reviewed by the user before implementation.
- YAGNI (You Ain't Gonna Need It): Never build code until absolutely necessary.
- Delete aggressively: Less code = Less bugs.
- Simple first: Always start with the simplest most obvious solution first. Improvements can be made iteratively afterwards.
- Self-documentation: Code should always be self-documenting. Always prioritize readability and interpretability of written code. 
- Fail fast: Explicit errors beat silent failures.
- Update relevant code comments, documentation, and docstrings when editing code. Docstrings must be written in the Google format for Python docstrings.
